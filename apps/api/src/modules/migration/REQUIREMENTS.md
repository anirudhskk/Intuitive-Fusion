## In scope

### FR-0655 · Must
The platform shall support ingestion of a customer's existing procurement and contract records from prior systems — structured exports, database extracts or document repositories — as part of onboarding.

**Acceptance:** Given a customer export in a supported format, when migration runs, then procurement and contract records are created in the platform and the count of records loaded reconciles to the source extract.

> ⚠ Open client query — see register Notes column.

### FR-0660 · Must
Migrated records shall be automatically linked into the platform's native record structures — for example a migrated contract linked to its migrated originating procurement or tender where that relationship exists in the source data — rather than loaded as unlinked, standalone records.

**Acceptance:** Given source data containing a contract and its originating procurement, when migration completes, then the two records are linked in the platform and the relationship is navigable without manual intervention.

> ⚠ Open client query — see register Notes column.

### FR-0665 · Must
The system shall run a data validation and profiling pass on migrated records prior to cutover, producing an exceptions report covering missing mandatory fields, unparseable dates or values and duplicate records, for manual reconciliation before the records are relied upon operationally.

**Acceptance:** Given a migration batch containing incomplete and duplicate records, when the validation pass runs, then an exceptions report itemises each issue by record and category, and cutover cannot be signed off with unreviewed exceptions.

> ⚠ Open client query — see register Notes column.

### FR-0670 · Must
Migrated historical records shall be distinguishable from natively created records via a source-system flag, while remaining fully searchable, reportable and subject to the same access controls as native records.

**Acceptance:** Given a migrated record, when it is viewed or reported on, then a source-system flag identifies it as migrated, and it responds to search, reporting and access controls identically to a native record.

> ⚠ Open client query — see register Notes column.

### FR-0675 · Must
Migration shall include AI extraction from legacy contracts of obligations, KPIs, deliverables, SLAs and optional extensions, with contract management records and alerts generated automatically — including default pre-expiry alerts and clause-derived notice-period alerts.

**Acceptance:** Given a migrated legacy contract stating a six-month termination notice, when extraction completes, then a contract management record is created with obligations and KPIs populated, a default pre-expiry alert is set, and an alert is scheduled at eight months before expiry.
